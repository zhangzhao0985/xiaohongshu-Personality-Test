# 你的什么欲望最强 · 专属欲望档案

一个给小红书用的「人格 / 欲望」付费测试网站，**带后端验证**。买家在小红书下单 → 拿到订单编号 → 在网页里**先验证订单编号** → 验证通过才能开始测试 → 生成专属《欲望档案》 → 一键生成分享长图。

> 小叭你好 👋 这份说明就是写给你的。日常你只会用到两件事：**① 改前端 `app.js` 顶部的 `CONFIG`（店铺名/价格）；② 在管理页 `/admin` 录入订单号**。其它都不用动。

## 🌸 用户体验流程

1. **首页**：主题「你的什么欲望最强？」，价值点 + 价格（原价 ¥3，折后 ¥1.49）。进首页会弹出小叭的「主题抽奖通知」，引导去下单拿订单编号。
2. **验证门（先验证再测试）**：点「开始测试」后，先要求输入**订单编号**。后端自动校验：通过才放行，错误会再次引导购买。
3. **20 道情境题**：题目由后端下发（前端拿不到答案与维度的对应关系，无法刷答案）。
4. **结果页**：完整《欲望档案》——顶部「你的专属属性」（8 选 1）+ 一句话概述、8 大欲望光谱（带百分比进度条）、属性的 400+ 字完整分析、隐藏面、想我指数、小叭寄语，全部直接可见（因为已经在前面验证过）。
5. **一键生成分享长图**：用 canvas 现画一张竖版海报，长按保存 / 下载，发到小红书。

## 🚀 本地先跑起来试试（3 步）

先装 [Node.js](https://nodejs.org/)（16 以上，装 LTS 即可）。

1. **设置口令**：把项目里的 `.env.example` 复制一份、改名为 **`.env`**，用记事本打开，把这一行改成你自己的口令：
   ```
   ADMIN_TOKEN=改成只有你知道的一串字符，比如 xiaoba-9527-abc
   ```
   其它行先不用动（`TOKEN_SECRET` 留空会自动生成）。
2. **启动**：在项目文件夹里运行 `node server.js`（或 `npm start`）。看到 `服务已启动` 就成功了。
3. **打开**：
   - 测试页：http://localhost:8787
   - 管理后台：http://localhost:8787/admin —— 在口令框输入你第 1 步设的那串，就能进去录订单号。

> 前后端是**同一个服务**：`server.js` 既托管网页，也负责验证/出题/计分。零依赖、不用 `npm install`。

### 🔑 两个“口令”分别是什么（看这里就懂）

| 名字 | 是什么 | 你要做什么 |
|---|---|---|
| `ADMIN_TOKEN` | **后台密码**。保护 `/admin` 管理页，只有你能进去录订单号。 | **自己想一串**写进 `.env`；进 `/admin` 时输入同一串。 |
| `TOKEN_SECRET` | **防伪密钥**。服务器内部用它给“已验证”的登录凭证签名，防伪造，你不会在任何界面输入它。 | **可留空**（自动生成）。正式上线建议也自己填一串随机字符。 |

> 两串都写在 `.env` 文件里，改完**重启服务**即可生效。`.env` 不会进代码仓库（已在 `.gitignore`）。

## ⚙️ 你需要改/用的地方

### A. 前端展示信息 —— `app.js` 顶部 `CONFIG`
```js
const CONFIG = {
  SHOP_NAME: "待补充",   // 你的小红书店铺名
  SHOP_URL: "",          // 可留空；填了弹窗里会出现「前往店铺 →」按钮
  PRICE_NOW: "1.49",
  PRICE_OLD: "¥3",
  API_BASE: "",          // 前后端同服务就留空；分开部署时填后端域名
};
```

### B. 后端配置 —— 环境变量（见 `.env.example`）
| 变量 | 作用 | 默认 |
|---|---|---|
| `ADMIN_TOKEN` | **必填**。进管理页、管理订单号的口令 | 空（不设则管理功能不可用）|
| `TOKEN_SECRET` | 登录令牌签名密钥。留空会自动生成并存到 `data/.secret` | 自动生成 |
| `PORT` | 端口 | `8787` |
| `ALLOW_ORIGIN` | 允许的前端来源，分开部署时填前端域名 | `*` |
| `MAX_DEVICES_PER_CODE` | 一个订单号最多可在几台设备解锁 | `2` |
| `TOKEN_TTL_DAYS` | 验证后多少天内免重复输入 | `30` |
| `ACCEPT_ANY_LONG_NUMBER` | 任意 8 位以上纯数字直接通过（慎开）| `false` |

### C. 录入订单号 / 发货对接 —— 管理页 `/admin`
打开 `/admin`，填入 `ADMIN_TOKEN`，即可：
- **批量录入订单号**：把小红书后台**导出/复制的订单号**粘进来（一行一个，或逗号分隔）。买家输入对应订单号即可自动解锁。
- **生成解锁码**：一次生成若干随机解锁码，贴到商品/自动回复里发给买家。
- **总览 / 作废**：查看每个码的使用状态、设备数，必要时作废。

> ⚠️ **关于“自动对接小红书”**：小红书目前对小商家几乎不开放订单核验接口（需要开放平台/企业资质），所以做不到“零操作全自动同步”。本方案做到的是**对买家全自动**：你把订单号录入一次（或用导出列表批量粘贴），之后买家验证、放行、防重复都是自动的。等你有了开放平台资质，可以再把录入这步也自动化。

## 🔒 它怎么防绕过 / 防重复使用

- **防绕过**：题目和计分**都在后端**，前端代码里没有任何题目答案与维度的对应关系；不先通过订单验证，连题目都拿不到，更算不出结果。
- **防重复使用**：每个订单号只能绑定有限台设备（`MAX_DEVICES_PER_CODE`，默认 2，方便手机+电脑/清缓存）；超出就拒绝，并提示联系小叭。
- **防爆破**：验证接口按 IP 限流。
- 验证通过后会发一个**签名令牌**（HMAC，无法伪造），有效期内买家无需重复输入订单号。

> 说明：这是“轻量但够用”的方案，适合小红书小店规模。它不是银行级风控——比如买家把自己的订单号给别人、且对方在你设定的设备数内，仍可能共用。把 `MAX_DEVICES_PER_CODE` 设为 1 可最严格。

## 🌐 部署上线（Node 服务器）

本服务是标准 Node，可部署到 **香港 / 海外 / 国内** 任意能跑 Node 的服务器。

> 📌 **要不要备案？** 服务器放**海外/香港 = 免备案**（多数测试站的做法，把 `CONFIG.ICP_BEIAN` 留空即可）；服务器放**大陆 = 必须 ICP 备案**并显示备案号。详细两种方式对比和保姆级步骤见 **[DEPLOY.md](DEPLOY.md)**。

通用步骤：
1. 把代码传上去，设置环境变量 **`ADMIN_TOKEN`**（必填）和 **`TOKEN_SECRET`**（建议设，见下）。
2. 启动命令：`node server.js`（或 `npm start`）。平台给的 `PORT` 会自动生效。
3. 拿到访问网址，放到小红书主页简介 / 商品详情 / 私信里。

**两个一定要注意的点：**
- 📦 **数据要持久化**：订单数据存在 `data/orders.json`。如果平台的磁盘是“临时的”（部分免费托管重启就清空），订单记录会丢。请选**带持久化磁盘/卷**的方案（如带 Volume 的 Railway、或一台小 VPS / 国内轻量服务器），把 `data/` 放在持久化目录。
- 🔑 **设置 `TOKEN_SECRET` 环境变量**：这样即使重启、即使 `data/.secret` 丢了，已发出的登录令牌也不会失效。
- 🇨🇳 **大陆访问**：海外服务器（Render/Railway 等）大陆访问可能不稳。若主要面向大陆用户，建议用**国内服务器并完成域名备案**，速度和稳定性都更好。

前后端也可以分开部署（前端放静态托管、后端单独跑），这时把前端 `CONFIG.API_BASE` 填成后端域名，并把后端 `ALLOW_ORIGIN` 设成前端域名即可。
